## 2. Put the fixed code live (about 10 minutes)

You need: **VS Code** (your editor), the **zip** I gave you (`Binglesignal-fixed.zip`), and your GitHub repo folder on your laptop.

1. **Unzip** `Binglesignal-fixed.zip` (right-click → Extract All). You get a folder called `Binglesignal-main`.
2. **Open your repo folder in VS Code**: VS Code → menu **File → Open Folder…** → pick the folder of your project (the one that is connected to GitHub).
3. **Copy the new files in.** Open the unzipped `Binglesignal-main` folder in Windows Explorer, select **everything inside it** (Ctrl+A), copy (Ctrl+C), go to your repo folder, paste (Ctrl+V), and choose **Replace the files in the destination**. (There is no `node_modules` folder in the zip on purpose.)
4. **Delete one old file.** In VS Code's left panel open `public`, right-click **`ads.txt`** → **Delete**. (Copying cannot delete files. This is the advertising file, and the site no longer shows ads.)
5. **Check everything still works.** In VS Code: menu **Terminal → New Terminal**. Type these two lines, pressing Enter after each:
   ```
   npm install
   npm test
   ```
   At the bottom you should see **`# pass 233`** and **`# fail 0`**. If you see anything red, stop and use the prompt in Section 9, item 7.
6. **Send it to GitHub.** Click the **Source Control** icon in VS Code (the branch icon on the left). Type a message like `Tester fixes: trust, news quality, light mode, pricing page`. Click **✓ Commit**, then **Sync Changes** (or **Push**).
7. **Wait 1–2 minutes.** Cloudflare builds it by itself: Cloudflare dashboard → **Workers & Pages** → your project → **Deployments**. The newest line should say **Success**.
8. Open `https://binglesignal.com` and press **Ctrl+Shift+R** (hard refresh) so your browser drops its old copy.

> The first time after deploy, the Markets card can take up to 5 minutes to appear (it is cached). The headline fixes (style, India label, shopping/zoo removal) apply immediately to the stories already stored.

## 4. The switches only you can flip (about 10 minutes)

### 4A. Make `www.binglesignal.com` open (tester point 6)

Do this in **Cloudflare**. The words in **bold** are what to look for; Cloudflare sometimes moves buttons around.

**Minimum (1 minute):** Cloudflare dashboard → **Workers & Pages** → click your project → **Settings** → **Domains & Routes** → **Add** → **Custom domain** → type `www.binglesignal.com` → **Add domain**. Wait 1–2 minutes. Now `www` opens the same site.

**Better (2 more minutes), so everyone ends on one address:** Cloudflare dashboard → click **binglesignal.com** → **Rules** → **Redirect Rules** → **Create rule**:
- Rule name: `www to apex`
- **If incoming requests match:** Custom filter expression → Field **Hostname** · Operator **equals** · Value `www.binglesignal.com`
- **Then:** Type **Dynamic** · Expression `concat("https://binglesignal.com", http.request.uri.path)` · Status code **301** · tick **Preserve query string**
- **Deploy**.

### 4B. Turn on the secure lock for everyone (tester point 7)

Cloudflare dashboard → click **binglesignal.com** → **SSL/TLS** → **Edge Certificates** → switch **Always Use HTTPS** to **ON**. Then also switch **Automatic HTTPS Rewrites** to **ON**. (Under **SSL/TLS → Overview**, the mode should be **Full**.) Your site already tells browsers to insist on https once they've visited once.

### 4C. Make "Forgot password?" actually send emails (tester point 25)

Do this in **Supabase** (supabase.com → your project).

1. **Authentication → URL Configuration**
   - **Site URL:** `https://binglesignal.com`
   - **Redirect URLs:** add `https://binglesignal.com/` and `https://binglesignal.com/**`
   Without this, the reset link and Google sign-in cannot return to your site.
2. **Authentication → Emails → SMTP Settings** (or **Authentication → Settings → SMTP**): turn on **Enable Custom SMTP** and enter your email service. Easiest free option: **Resend** (resend.com): verify `binglesignal.com` there, create an API key, then use host `smtp.resend.com`, port `465`, username `resend`, password = your API key, sender `support@binglesignal.com`.
   Why: Supabase's built-in email sender is only meant for testing. It is heavily rate-limited and only delivers to your own team's addresses, so real readers would never get the reset email. If you already set up custom SMTP, skip this.
3. **Test:** open binglesignal.com → **Sign in** → type your own email → **Forgot password?** → **Send reset link** → open the email → click the link → you land on the site with **"Choose a new password"**.

## 11. If something goes wrong (undo)

- **Roll back the whole release:** Cloudflare dashboard → **Workers & Pages** → your project → **Deployments** → pick the previous successful one → **Rollback**.
- **Only the homepage misbehaves:** in `wrangler.toml` change `run_worker_first = ["/api/*", "/"]` to `run_worker_first = ["/api/*"]`, commit and sync. The site then works exactly as before; only the "headlines inside the HTML" feature switches off.
- **Undo in Git:** VS Code → Source Control → **⋯** → **Commit → Undo Last Commit**, or in the Terminal: `git revert HEAD` then `git push`.

## 12. Things you should know (honest notes)

- **Old stored stories** are cleaned the moment they are served (style, India label, junk removal). The stored copies themselves are replaced by the robot over the next days (stories expire after 7 days).
- **Google links** are replaced gradually (up to 150 per robot run), so a few can still be Google links in the first day.
- **Markets numbers** come from Yahoo Finance's public feed. It is free and works without a key, but it is unofficial and delayed. If you grow, switch to a paid data feed (prompt 2). The card says "Delayed quotes · Yahoo Finance".
- **Title Case** is used for all news headlines because it can never damage names (Tata, iPhone, OpenAI). Video titles keep the channel's style.
- **Light mode** is not automatic by default, because the dark-blue and gold look is what the tester praised. Prompt 3 changes that if you prefer.
- **The hidden Email Beta pages** still use the US spelling "summarize" in a few labels. I left them alone because that code matches those exact words; they are off while `emailBeta:false`.
- **`public/feed.json`** is only a backup copy the homepage uses if the live feed is down. It is old (6 November) and gets refreshed by the robot.
- **Site health workflow:** it needs at least 20 stories in `/api/teaser`. The new filters keep it far above that when the database is healthy.
